# BPSC Nexus | Prelims Test Series Bot

A starter Telegram bot using Python, Telegram Bot API, and Neon PostgreSQL.

## Current features

- `/start`: registers or updates the student's Telegram profile.
- `/tests`: lists up to 30 published tests.
- `/help`: lists available commands.
- Connects to Neon using `DATABASE_URL`.
- Reads credentials from environment variables, not source files.

Interactive exam attempts, timers, answer submission, marking, and performance analytics are **not implemented yet**. They are planned for the next development stages.

## Database prerequisite

Create the six tables in `schema.sql` in your dedicated Neon project before deploying. If you already ran the schema manually in Neon, you do not need to run it again.

## Environment variables

Set both variables in your hosting provider's private Environment settings:

- `BOT_TOKEN`: token generated by @BotFather.
- `DATABASE_URL`: Neon PostgreSQL connection string. Use the pooled connection string if available and keep SSL enabled (`sslmode=require`).

Never put real tokens or passwords in GitHub files, screenshots, Telegram chats, or public logs. If a token is exposed, revoke it with BotFather and create a new one.

## Run locally (optional)

Python 3.11 or newer is recommended.

```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python bot.py
```

Set `BOT_TOKEN` and `DATABASE_URL` in your shell before running.

## Deploy on Render

1. Push this repository to GitHub.
2. In Render, create a **Background Worker** from the repository.
3. Build command: `pip install -r requirements.txt`
4. Start command: `python bot.py`
5. Add `BOT_TOKEN` and `DATABASE_URL` as secret environment variables.
6. Deploy and inspect the logs. Look for `Database connection verified.` and `Starting BPSC Nexus Telegram bot.`

Free worker availability and limits can change. Confirm the current plan shown in Render before deployment.

## Publish a test

Insert a row in the `tests` table and set `is_published = TRUE`. The test will then appear in `/tests`. Do not publish a test until its questions have been added to `test_questions`.

## Security and operational notes

- Use a separate Neon project for this bot.
- Use a database role with only the privileges required by the bot if you later create separate admin tooling.
- Back up your question bank and important attempt data.
- This is a starter implementation, not a completed exam engine.
